# Provozní poznámky a pasti

Přeneseno 4. 8. 2026 z Claude memory (`reference_message_queue_next_prefix`), kde to bobtnalo na 12 KB.
Jsou to hard-won zjištění o cmuxu a Claude Code, která přežijí konkrétní implementaci.


Claude Code has **no native message queue** (steering only; anthropics/claude-code #50246, #63190, #30677). Messages typed mid-turn bypass ALL Claude hooks, so hook/plugin queues cannot intercept them.

**Installed solution: `~/Sites/cmux-claude-queue`** (git repo, README + commit history = the source of truth for design, flow and changelog; do NOT re-document it here). Shape: a Carbon hotkey daemon (`cmux-claude-queue-hotkeyd`, Opt+Enter, registered only while cmux is frontmost, Opt+Shift+Enter opens the queue manager pane) spawns `cmux-claude-queue capture`, which scrapes the input box and either submits (idle) or appends to a per-surface file queue (running). Delivery is pumped by the Claude Code statusline (`statusLine.command`, chains David's vibe-ads statusline) and by cmux notification hooks. `~/.local/bin/cmux-claude-queue` is a **symlink into the repo**. `!qq <text>` (`~/.local/bin/qq`) is the typed no-focus-steal alternative. The old `next:` soft convention stays in `~/.claude/CLAUDE.md` as manual fallback.

**Hard-won gotchas (these outlive the implementation):**
- **cmux socket `cmuxOnly` mode rejects orphaned clients**: a nohup'd/detached process (PPID 1) gets `Broken pipe (errno 32)` / "Access denied — only processes started inside cmux can connect" on every cmux CLI call, even `ping`. Helpers must be cmux descendants: action tabs and notification hooks qualify, detached daemons never. (Current setup avoids this with `automation.socketControlMode: "password"` + `automation.socketPassword` in cmux.json.)
- **Notification hooks run via /bin/sh with minimal PATH** — `cmux` is not on it; fall back to `/Applications/cmux.app/Contents/Resources/bin/cmux`. Hook must answer within `timeoutSeconds`, and its JSON policy from stdin must be echoed back on stdout (anything else goes to a log, not stdout).
- **Keystroke injection (send/send-key) is silently swallowed while the user actively types/focuses the surface** — even repeated `enter` presses can do nothing. Always verify delivery: watch `~/.cmuxterm/events.jsonl` for a new `agent.hook.UserPromptSubmit` with `"claude-<sessionId>"`; retry on later ticks until confirmed. Read the input box first and back off if it holds a user draft (never \x15 over it).
- **Esc interrupt is invisible to everything hook-based** (verified in events.jsonl): pressing Esc mid-turn emits NO Stop hook, no sidebar update (stays "Running"), no turn-complete notification. Both `agentLifecycle` and the newest-UPS-vs-Stop check say "running" forever. Only the live TUI screen arbitrates, via `esc to interrupt|\(\d+m? ?\d*s\s*·|\d+m? ?\d*s\s*·\s*[↓↑]` — the third alternative matters: **while a SUBAGENT runs the TUI shows "◯ general-purpose … 6m 57s · ↓ 110.0k tokens" WITHOUT parentheses**, so a paren-only regex judges a busy session idle.
- **Steering messages do NOT fire the UserPromptSubmit hook** (docs + research 2026-07-14); an earlier "confirmed" steer delivery was a false confirm from a same-window foreign submit. A UserPromptSubmit hook also cannot rewrite prompt text (only additionalContext/block).
- **Anything hook- or statusline-spawned can be SIGKILLed between any two lines.** cmux reaps notification-hook processes when their notification clears, and Claude Code kills a statusline command still running when the next refresh comes due. Both caused live duplicate deliveries. Design rule: every multi-step state mutation needs record-first or atomic-rename; long work goes into a detached background job serving a cache.
- **Never live-edit an installed script that background ticks execute** (here every ~15 s while any queue is non-empty). A multi-Edit refactor left a window where a just-removed function was still called; command-not-found made the running-turn guard falsy and injected a queued prompt into a RUNNING turn, in two sessions at once. Stage on a copy and `mv` atomically.
- **macOS /bin/bash is 3.2**: no `$BASHPID` (under `set -u` the reference kills the subshell), no `read -i`, no fractional `read -t`, no reliable rc>128; empty array + `"${arr[@]}"` under `set -u` is an unbound error. Test explicitly through `/bin/bash` — a Bash-tool shell can pass where production (shebang `/bin/bash`) dies.
- **David's interactive zsh has a `find` function → bfs**, which rejects `-newermt '-N seconds'` ("Invalid timestamp"). Inline age-check testing in a Bash-tool shell false-fails; scripts get `/usr/bin/find` (functions do not propagate). Pin `/usr/bin/find` anyway.
- **Cross-workspace focus discipline:** `cmux rpc surface.focus`/`workspace.select` on a surface in a NON-selected workspace YANKS the user's workspace selection, and `workspace.last` has no history to undo it. Check `workspace.current == intended ws` first. RPC calls with omitted ids (`surface.split '{"direction":...}'`, `surface.create '{}'`) default to the USER'S focused surface — always pass explicit ids. `surface.split`'s `initial_command` spawns the raw process without a shell (surface dies instantly unless it is a long-lived binary); use `cmux send` + enter, or exec.
- **Statusline cost is real:** ccstatusline (bun) measured 4.7 s cold under load 20 vs 0.5 s cached. With ~37 open sessions re-running it every 5 s, the statusline storm itself was a large chunk of permanent background load — caching per session REDUCES total load even at a shorter refresh interval.
- **Claude Code `!` bash mode:** a MULTI-byte chunk starting with `!` is paste-treated and stays literal text, but a SINGLE-byte `cmux send '!'` into an empty input DOES engage shell mode. Once engaged, multi-byte sends are fine + `send-key enter`. A `!` command submitted mid-turn is deferred and executes after the turn ends (as a claude child = cmux descendant with socket access).
- **`tool_input_length`** in the redacted UserPromptSubmit payload = `len(json.dumps({"prompt": text}, separators=(",",":")))` — COMPACT JSON, no spaces ("test" → 17). Never validate such a formula at offset 0 over the whole event history; a coincidental match will pass.
- **cmux restart regenerates ALL workspace/surface UUIDs**; `claude-hook-sessions.json` only re-registers a session when its next hook fires. Resolve a session's surface via `cmux rpc surface.list '{"workspace_id":...}'` → `resume_binding.kind == "claude"` (live truth, `checkpoint_id` = claude session uuid); the store is fallback only, and its session ids appear bare AND `claude-`-prefixed across versions.
- **AskUserQuestion renders BETWEEN the input-box separators**, so a box scraper reads it as a "draft". Treating it as empty would be an injection risk (Enter = picks an option).
- **Slash commands (/compact, /clear, skills…) emit NO UserPromptSubmit** — they run inside the TUI. An event-log confirm can never succeed, so the pump resent a queued `/compact` every ~15 s tick, 14x, until manually deleted (2026-07-28, fixed in 7c69e6a: box-cleared-after-Enter is the confirmation for `/`-token lines, plus a 3-strike resend cap for anything else unconfirmable). The TUI renders a submitted slash command as TWO `❯ /cmd` rows (echo + record) — not a double run; count result lines instead.
- **cmux control socket direct (2026-07-28, commit fe88cc3): ~2 ms/request vs ~140 ms per CLI spawn** (~110 ms of that inside the CLI binary itself, NOT the app). Connect `~/.local/state/cmux/cmux-<uid>.sock` (or path from `last-socket-path`), auth = plain text line `auth <password>\n` → `OK: Authenticated` (password: `~/.local/state/cmux/socket-control-password`, fallback cmux.json `automation.socketPassword`), then NDJSON `{"id":N,"method":"...","params":{...}}` → `{"ok":true,"id":N,"result":{...}}`. Working v2 methods: `workspace.current`, `surface.list`, `surface.read_text` (returns NBSP `\xa0` where CLI read-screen renders spaces — normalize!), `surface.send_text`, `surface.send_key`, `surface.focus`, `notification.create_for_surface` ({surface_id,title,body}, reaches notification hooks). `debug.terminal.read_text` from docs/v2-api-migration.md does NOT exist on release builds; discover real names via `strings .../Resources/bin/cmux | grep -E '^(surface|workspace)\.'`.
- **External-editor capture (2026-07-29, commit 8097032):** Claude Code Ctrl+G (`chat:externalEditor`, also Ctrl+X Ctrl+E) writes the draft to `$CLAUDE_CODE_TMPDIR/claude-<uid>/claude-prompt-<uuid>.md`, spawns `$EDITOR` (env from session start; settings.json `env` can set it) and restores the box from the file on editor exit — truncate = native box clear, file holds EXACT text incl. blank lines the scrape can't see, `CMUX_SURFACE_ID` is in the editor's env. Works mid-turn. Synthetic `\x07` via cmux send triggers it MOSTLY but was seen swallowed once during early-turn streaming (same "keystroke silently swallowed" class); real keypresses are the production path. `send-key ctrl+g`/`ctrl+u` are silent no-ops (unknown key names). Passthrough real editor must be `zed --wait` — plain `zed` exits immediately and the TUI restores the unedited file. David's env: EDITOR=zed, VISUAL unset (zshrc:187).
- **Multi-line input-box facts (2026-07-28):** Ctrl+U (\x15) kills only the CURRENT line of a multi-line draft (hit live — only the last line vanished). Full clear = per-row cycle `\x0b\x15\x7f` (Ctrl+K, Ctrl+U, Backspace joins up), overshoot is free (all no-op on an empty box); verify via re-read AFTER ~60 ms (TUI redraw lag makes an immediate read show stale content). `send_text` with raw `\n` SUBMITS each line (mid-turn they land in Claude Code's native queued-messages buffer); bracketed-paste markers do NOT pass through cmux send (rendered literally). Synthetic multi-line draft for tests: per line send `text\` + send-key enter. Another ghost-text variant renders in the box: "Press up to edit queued messages".
- **statusLine `refreshInterval` empirics (2026-07-28, commit 0bdb294):** unit is seconds; `1` is honored (median gap 1 s measured across 35 sessions); a settings.json edit applies to RUNNING sessions within seconds, no restart needed; every open session refreshes continuously even while idle, so with ~35 sessions the wrapper's per-run cost multiplies into permanent background load — hot path must stay bash-builtin-only (substring sid extract + `sidmap-*` file cache halved CPU 36→18 ms/run; re-validate the map at most every 30 s while a queue pends, or an orphaned queue makes every session pay 2 plutil/s forever). Opt-in cadence tracing: create `~/.claude/prompt-queue/debug-cadence` and each wrapper run appends `epoch sid`. When testing queue/pending paths, ALWAYS use a fake surface id — a real one races the delivery pump into a live session.
- **Claude Code ghost-text prompt suggestions render inside the input box with the same `❯ ` prefix** and scrape identically to a typed draft (read-screen keeps no style attributes) — a "user draft in box" hold-off can therefore block delivery forever. Discriminator (verified live): ghost text sits over an EMPTY buffer; after typing one char the box holds just that char (draft would hold draft+char), and backspace undoes the probe — the suggestion re-renders on an empty box. Probe only on an idle session.
- cmux `shortcuts.bindings` is a fixed enum of built-ins, but **custom actions may define their own `shortcut` field**. Action targets are only `currentTerminal`/`newTabInCurrentPane` — no background/silent run exists.
- Assumes one Claude session per workspace; `agentLifecycle` idle states are `idle` AND `needsInput`.
